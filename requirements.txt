# app.py no longer calls osmnx directly (see "ARCHITECTURE" in its own
# docstring — real road-network queries moved client-side to OSRM). osmnx
# is still used by src/city_graph.py's get_or_build_street_graph(), which
# only prefetch_street_graphs.py calls now; it's kept here for that offline
# tool, not because the live app needs it.
#
# osmnx, dwave-samplers, and dwave-system all carry an upper bound (<3, <2,
# <2 respectively) instead of an unbounded >=, unlike the pure-Python
# dependencies above/below them — these three pull in native/C-extension
# build steps (osmnx's own geo stack; dwave-samplers' and dwave-system's
# C++ solver/minor-embedding internals via minorminer), so a future major
# release is more likely to change a build requirement or a function
# signature this project actually calls, not just add features. This
# project is tested against osmnx 2.1.1 and dwave-samplers/dwave-system
# 1.8.0/1.36.0 specifically (this sandbox's installed versions while these
# pins were added) — the upper bound just stops an untested future major
# from being silently picked up by a fresh install.
#
# flask-limiter adds basic per-IP rate limiting to /api/solve and
# /api/solve_fleet (20 requests/minute) so a public demo URL can't be
# trivially hammered. It's automatically disabled while running under
# pytest (see app.py) so the test suite is never rate-limited.
#
# gunicorn is only needed when deploying app.py to a cloud host (Render,
# Railway, etc.) — see the "Deploy to the cloud" section in README.md.
# It's unused for local runs (python3 app.py uses Flask's own dev server).
#
# requests is a DIRECT dependency (not just transitive via osmnx/folium)
# as of src/traffic_provider.py's GoogleRoutesTrafficProvider — the one
# real, working live-traffic API integration in this project
# (TRAFFIC_PROVIDER=google_routes). It's only exercised at runtime if that
# provider is selected AND a GOOGLE_ROUTES_API_KEY is configured; the
# default TRAFFIC_PROVIDER=simulated never imports it for real network use.
#
# dwave-system IS listed above (unlike ortools/qiskit/playwright below) —
# this used to be an optional extra, installed separately only for
# run_on_real_quantum_hardware.py's one-off pitch-deck script. It's a
# default dependency now because method="qpu" is a first-class option in
# the LIVE app too (the "Real QPU (D-Wave annealer)" dropdown choice, wired
# through /api/solve and /api/solve_fleet — see src/qpu_solver.py), and a
# deployed server can't offer that option at all if the package was never
# installed on it in the first place. Installing the package does NOT by
# itself make real QPU solves work — see README.md's "Real quantum
# hardware validation" section: you still need your own D-Wave Leap API
# token (DWAVE_API_TOKEN) from a plan that actually includes API access,
# which nobody else can supply on your behalf. That last part is NOT free
# self-serve signup — D-Wave's own support docs say the free Trial plan
# does not include an API token, only their pre-built dashboard demos; a
# working token needs a paid Leap plan or an accepted application to
# D-Wave's Leap Quantum LaunchPad program. Confirmed installing cleanly
# (no native build step failed) in this project's own dev/test
# environment; Render's build log is the real check for your deployment
# specifically.
#
# ortools is also NOT listed above on purpose — it's a large native
# dependency used only by src/ortools_baseline.py, an optional third
# comparison point in the benchmark suite (Google's own production
# routing solver, alongside the hand-rolled 2-opt baseline). Neither the
# live app nor the core benchmark needs it; tests/test_ortools_baseline.py
# and benchmark.py both skip that comparison cleanly when it's absent.
# Install it separately when you want that comparison:
#     pip install ortools
#
# qiskit is also NOT listed above on purpose — it's used only by
# src/qaoa_solver.py, a second "quantum-inspired" solver (QAOA, a
# gate-based variational quantum circuit, run on a classical statevector
# simulator) for the same QUBO the live app already builds, kept as a
# research/pitch-deck credibility module rather than a live-app dependency
# (see qaoa_solver.py's own docstring for the honest reasons why it isn't
# wired into /api/solve). tests/test_qaoa_solver.py and run_qaoa_demo.py
# both skip cleanly when it's absent. Install it separately:
#     pip install qiskit
#
# pytest is also NOT listed above — it's a dev-only tool for running the
# tests/ suite, not something the app or a deploy needs. Install it
# separately to run tests:
#     pip install pytest && pytest tests/ -v
#
# The frontend helper tests (tests/frontend/) need only Node.js 18+ (for
# its built-in test runner) — no npm install, no extra Python dependency:
#     node --test tests/frontend/*.test.js
#
# tests/test_layout.py (real-browser layout/regression checks — see its
# own docstring for why it exists) needs Playwright, which is NOT listed
# above on purpose: it's a dev/CI-only tool, and the test file skips
# itself cleanly if it's missing rather than failing the rest of the
# suite. Install it separately to run those tests:
#     pip install playwright && playwright install --with-deps chromium
#     pytest tests/test_layout.py -v
